# 技术路线决策表

装什么、不装什么、什么时候换。**每条都给出取舍，不做"都装上"的建议。**

---

## 渲染 / 性能

### 1.21.1 Fabric 的标准栈（无争议）

| 层 | 模组 | 作用 |
|---|---|---|
| 渲染器 | Sodium | 区块渲染重写，必装 |
| 渲染选项 | Sodium Extra + Reese's Sodium Options | 补全视频设置项 |
| 服务端逻辑 | Lithium | 实体/方块 tick 优化 |
| 内存 | FerriteCore | 降低模型/方块状态内存 |
| 通用修复 | ModernFix | 启动与内存问题兜底 |
| 实体剔除 | EntityCulling | 视野外实体不渲染 |
| 掉落物 | Clumps | 经验球合并 |
| 区块线程 | C2ME | **仅 alpha 分支可用，见下** |

**不该加**：Embeddium、Optifine、Canvas、VulkanMod（与 Sodium 互斥）；
第二个"优化整合"类模组只会增加 mixin 面积。

### C2ME 的取舍

1.21.1 只有 `0.4.0-alpha.x`，没有稳定版。它的 `c2me-opts-natives-math` 子模块
`depends: java >= 25`，在 Java 21 上会被跳过。

- 保留：区块生成/加载更快，代价是 alpha 的未知回归。
- 移除：更稳，但大视距下加载变慢。

**判断**：视距 ≤ 8 且单人时，收益有限。**不追新版本号**，稳定的那个 alpha 就别动。

## 光影

| 方案 | 帧率量级（AMD 880M 核显 / 2560×1600） | 适用 |
|---|---|---|
| 无光影 | ~117 FPS | 建筑、长时间游玩、低配 |
| Complementary | ~54 FPS | 想要光影又不想太卡 |
| Photon | ~20–40 FPS | 不建议在这类核显上使用 |

**不要同时装多个光影**——`shaderpacks/` 里放几个都行，但 `iris.properties` 的
`enableShaders` 与 `shaderPack` 只能指向一个。

**与材质的搭配**：16x 像素风材质开写实光影会撕裂风格；16x + 无光影才是自洽路线。

## 动态光源

| 模组 | 特点 | 注意 |
|---|---|---|
| LambDynamicLights | 最成熟，手持物品/掉落物/岩浆都发光，与 Sodium 兼容 | 推荐 |
| Sodium Dynamic Lights | 更轻，但功能面窄 | 已装 Lamb 就别再装 |
| Dynamic Lights (旧) | 维护停滞 | 不用 |

**只装一个。** 装两个会出现光照叠加导致过曝或闪烁。

## 动画

### 分层，别混为一谈

| 层 | 模组 | 管什么 |
|---|---|---|
| 实体模型 | Entity Model Features (EMF) | 读 `.jem`，驱动实体骨骼动画 |
| 实体纹理 | Entity Texture Features (ETF) | 随机/发光贴图 |
| 动画数据 | **FreshAnimations 资源包** | 真正的内容，没有包就没有动画 |
| 世界动画 | Fancy World Animations (FWA) | 草/树叶摆动，**不碰实体** |
| 第一人称 | Punchy（+ 其内置资源包） | 挥臂、挖矿、持物姿势 |
| 摄像机 | smoothcamera / watut | 平滑跟随、说话口型 |
| 玩家模型 | skinlayers3d / playeranimator | 3D 皮肤层、骨骼 |

**关键**：EMF/ETF 只是引擎，`FreshAnimations` 是内容。引擎在、内容不在 = 没动画。

### 版本配套

EMF 与 ETF 互相声明 `breaks` 旧版本，必须成对升级：
EMF ≥ 3.3 配 ETF ≥ 7.2。跨大版本混用会出现模型不重建或纹理错位。

### 不要做的事

- 不要同时用 Optifine 的 CEM 和 EMF（互斥）。
- 不要在 EMF 里把 `allowedCEM` 设成非 `ALL`——会静默跳过大量模型。
- 不要为 1 个模型（如 bell）禁用整个动画栈。

## 材质

### 分辨率与动画包的兼容

| 分辨率 | 与 FreshAnimations | 备注 |
|---|---|---|
| 16x | 兼容 | 最稳，性能最好 |
| 32x | 通常兼容 | 内存与显存翻倍，核显谨慎 |
| 64x+ | 易出问题 | 需要更多显存，且常覆盖实体贴图导致动作异常 |

**实测教训**：换成 32x 后出现"动作全没了"，根因不是分辨率，而是**同时换了动画数据包**。
换材质时一次只换一样。

### 版本代差

`pack_format` 与游戏版本差 1 个大版本以内通常无害；差 2 个以上要预期
"个别方块丢模型"。用 `nopackcompatcheck` 能压掉警告，但压不掉属性差异。
**优先局部补 blockstate，而不是重做整套包。**

## 家具 / 装饰生态

同时装 4~5 套家具是常见的审美崩塌来源，也是注册表膨胀的主因。

| 生态 | 风格 | 何时保留 |
|---|---|---|
| Macaw's 系列 | 原版延伸、方块化 | 建筑党基础，几乎必留 |
| Refurbished Furniture | MrCrayfish 写实 | 想要"能用的家具" |
| Skniro's Furniture | 写实 | 与 Refurbished 二选一 |
| 方块小镇 Yuushya | 日式/精细 | 做庭院、街景时留 |
| 森罗物语 | 二次元 | 风格最跳，非主题向建议移除 |

**精简原则**：先看视觉语言，不看模组数量。同屏出现"写实沙发 + 像素椅子 + 动漫摆件"
比少 5 个模组更伤观感。

**已知问题集中区**：Skniro（缺模型 + 大量非 2 次幂贴图）、Macaw 门的 cherry waffle 系列（缺模型）。

## 小地图 / 导航

Xaero 的 Minimap + WorldMap 是配套，不是重复，两个都要装（共享 XaeroLib）。
Nature's Compass / Explorer's Compass 与它们不冲突。

**不要装第二个小地图**（JourneyMap 等）——会重复渲染，且键位冲突。

## 判断"该不该加一个模组"的四问

1. 现有模组里有没有已经覆盖这个功能的？（查 `mods/` 再决定）
2. 它和现有栈有没有 `breaks` 或同类竞争？
3. 它带来的 mixin 面积值不值得？（尤其 Camera / Renderer / Particle 这三处）
4. 出问题能不能单独关掉？（不能单独关的，风险更高）

四问里有一个答不上来，就先别加。
