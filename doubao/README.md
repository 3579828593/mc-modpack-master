## 一、这是什么

一套可以直接在**豆包**或**扣子（Coze）**上线的智能体素材，主题是「Minecraft 整合包为什么崩 / 糊 / 没动作 / 卡」。

包含：人设提示词 ×1、知识库文档 ×5、示例对话 ×3、可执行脚本 ×5、验收清单 ×1。

## 二、先说清楚一件事（很重要）

**豆包和扣子都不能运行 Python 脚本。** 它们能读知识库、能做推理、能按提示词输出，但没有本地执行能力。

所以这个交付包分两层：

| 层 | 在豆包/扣子上 | 说明 |
|---|---|---|
| **推理层** | ✅ 直接可用 | 判断症状、给出验证命令、解读用户贴回来的输出 |
| **执行层** | ❌ 不可用 | 审计脚本需要用户在自己电脑上跑，把输出贴回来 |

`04-工具包/` 里的脚本是给**用户**在自己电脑上执行的，不是给智能体调的。
智能体要做的是：告诉用户跑哪条、然后读懂结果——这部分能力写在 `02-知识库/04-审计输出解读.md` 里。

**不要**指望把 `mc_audit.py` 塞进知识库就能自动审计，那不会生效。

## 三、两条接入路径

### 路径 A：豆包 App 直接创建（简单，5 分钟）

适合：只想有个能问的助手。

1. 豆包 App → 我的 → 智能体 → 创建
2. 名称：`铁砧` / 简介：`Minecraft 整合包诊断`
3. **人设与回复逻辑**：粘贴 `01-人设提示词.md` 全文
4. **知识库**：上传 `02-知识库/` 下全部 5 个 md
5. 保存即可

限制：豆包自建智能体功能较简单，知识库检索偏向关键词匹配，长文档可能被截断。
建议把「05-降级诊断手册」放在第一个上传，它最常被命中。

### 路径 B：扣子（Coze）创建后发布到豆包（完整）

适合：要长期维护、要分享给别人用。

1. 扣子 → 创建智能体
2. **人设与回复逻辑**：粘贴 `01-人设提示词.md`
3. **知识库**：新建知识库，上传 `02-知识库/` 全部文件，分段方式选「自动分段」
4. **开场白**：建议用
   `我是铁砧。说症状，别说"崩了"——把日志最后 30 行贴给我，我给你三个原因和各自的改法。`
5. **推荐问题**（三个）：
   - 游戏一开就闪退，怎么定位
   - 第一人称动作没了，是不是模组坏了
   - 画面好糊，要不要换材质包
6. 调试满意后 → 发布 → 勾选「豆包」渠道 → 审核通过后出现在豆包智能体广场

平台能力（知识库、工作流、插件）以扣子实际界面为准，本包不依赖任何插件或工作流。

## 五、能力边界（贴给用户看的那版）

**能做**：判断症状属于哪类、给出可复制的验证命令、解读日志与审计输出、给最小介入的修复方案、区分「上游没修」与「本地配错」。

**不能做**：读你的文件、替你改配置、跑脚本、判断存档是否损坏、给模组打分或推荐替代品。

**让位**：做整合包与分发 → packwiz；开服 → 对应开服指南；写模组 → 模组开发工具链。

## 六、上线验收

按 `05-验收清单.md` 走一遍。**先测诚实性四条**（A1–A4）——如果它会张口就说「可能是模组冲突」，
说明人设里的「先取证」被弱化了，重新粘贴完整版。

## 七、怎么更新

上游仓库更新后，同步这三处即可：

1. `02-知识库/01~03` ← 仓库 `skill/mc-modpack-master/references/` 下同名文件
2. `04-工具包/scripts` ← 仓库 `skill/mc-modpack-master/scripts/`
3. `01-人设提示词.md` ← 仓库 `expert/mc-modpack-expert/agents/mc-modpack-expert.md`（需转成第二人称）

版号跟仓库走，当前 v1.3.0。

## 八、已知限制

- 知识库检索是关键词/向量匹配，不保证每次都命中正确段落。**短文档、标题像用户提问**的文件命中率更高。
- 平台可能自动精简超长人设。若发现「输出格式」丢失，优先压缩「语气」一节而不是删格式。
- 本包不含工作流编排，也不依赖插件。若平台支持工作流，可自行加「先问三样信息再回答」的强制节点。
