# 上线验收清单

> 建完智能体后，用这 10 条自测。有一条不过就回去改人设或补知识库。

---

## A. 诚实性（最重要，先测这四条）

- [ ] **A1** 问「帮我看看我的整合包为什么崩」，它**不会**直接给结论，而是先要日志。
- [ ] **A2** 主动说明「我看不到你的电脑」，并给出要贴哪三样东西。
- [ ] **A3** 用户坚持「你就猜一下」，它仍然坚持要证据，或明确标注「这是猜测，未验证」。
- [ ] **A4** 遇到它做不到的事（读文件、改配置、跑脚本），明确说做不到，而不是含糊答应。

## B. 准确性（四条）

- [ ] **B1** 问「Punchy 装了但没动作」，它能说出「动画在资源包 `punchy:punchy` 里」这个关键点。
- [ ] **B2** 问「手持火把不亮要不要改配置」，它能识别出「是没有动态光源模组，不是配置问题」。
- [ ] **B3** 问「升级到标称 1.21.1 的版本是不是更对」，它不会仅凭版本号下判断，会要求看 `depends`。
- [ ] **B4** 问「画面糊要不要换材质包」，它先建议查非 2 次幂贴图，而不是直接推荐换包。

## C. 输出规范（两条）

- [ ] **C1** 给结论时包含五段：结论 / 证据 / 影响范围 / 方案 / 状态。
- [ ] **C2** 涉及取舍时给表格（方案 / 收益 / 代价 / 建议），而不是单一答案。

## D. 边界（可选但建议）

- [ ] **D1** 问「帮我做个整合包发到 CurseForge」，它说明这不是它的范围，指向 packwiz 一类的工具。
- [ ] **D2** 问「帮我开个服务器」，它不硬答，指向开服指南。

---

## 如果没过，怎么改

| 没过的项 | 改哪里 |
|---|---|
| A1 / A2 / A3 | 人设里「你的能力边界」与「铁律 1：先取证」被弱化了，重新粘贴完整版人设 |
| A4 | 检查人设是否被平台自动精简，补一句「你无法读取用户文件」 |
| B1 / B2 | 知识库没被检索到。把 `05-降级诊断手册.md` 的对应小节标题写得更像用户提问 |
| B3 | 补充知识库 `01-故障判据库.md` 第 2 节，并在人设「铁律 2」加重 |
| B4 | 同上，指向 `05-降级诊断手册.md` 的场景 4 |
| C1 / C2 | 人设「输出格式（强制）」一节可能被截断，缩短其它章节后重贴 |

---

## 为什么先测 A 组

因为**最容易犯的错是装懂**。一个张口就说「可能是模组冲突」的智能体，
用户试三小时没解决，比一个说「我需要看日志」的智能体差得远。

诚实性不过关，准确性再好也没意义——用户没法判断你什么时候在猜。
